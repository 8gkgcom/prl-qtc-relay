# Relay · PRL / QTC 矿池转发

适用于 **Pearl（PRL）** 和 **Quantus（QTC）** 的矿池转发软件。使用 Go 编写，提供 Windows x64、Linux x64 单文件程序，通过网页配置端口、矿池、地区节点和转发抽水，支持手机访问。

**当前版本：v2.2.1**

[下载 v2.2.1 软件包（Windows + Linux）](https://github.com/8gkgcom/prl-qtc-relay/releases/download/v2.2.1/prl-relay-v2.2.1.zip) · [查看 Release](https://github.com/8gkgcom/prl-qtc-relay/releases/tag/v2.2.1)

点击下载链接，或在 Release 页的 **Assets** 中下载 `prl-relay-v2.2.1.zip`。解压后选择对应系统的可执行文件即可使用，无需安装 Go、数据库或其他运行环境。

## 功能

- **多端口转发**：每个端口独立设置币种、矿池、地区、连接方式、转发抽水比例和收款钱包。
- **TCP / SSL**：矿机接入和矿池上游分别设置；首次启动自动生成自签证书，后续启动复用，也可导入自己的证书。
- **矿池选择与测速**：内置 PRL、QTC 矿池和地区节点，可测 TCP / SSL 连接延迟，直接选用节点，也可自定义添加矿池。
- **最近 24 小时统计**：连接趋势、接受 / 拒绝 / 未知份额、上传 / 下载和份额平均响应时间，支持按端口查看与 CSV 导出。
- **端口查询页**：每个端口有独立查询地址，可设置访问密码；输入钱包后查看对应矿机、连接和最近 24 小时数据。终端查询页不展示抽水配置。
- **在线矿工**：查询页显示全部在线连接的矿工名、就绪状态、接入时间和连接时长，同名多个连接分别列出；支持搜索与分页。
- **网页重启**：系统设置中确认后重启程序，保存统计，保留配置和历史，服务恢复后提示重新登录。
- **日志与备份**：日志筛选、保存周期设置、设置导入导出、手动和定时数据备份、备份下载。
- **连接防护**：连接数量和速率限制、密码尝试限制、会话隔离、CSRF 校验、报文大小和超时限制。
- **网页管理**：端口、统计、矿池、日志、系统五个菜单，兼容桌面和手机浏览器。

## 快速开始

### Windows

1. 下载并解压软件包到固定目录，例如 `D:\Relay`。
2. 运行 `prl-relay-windows-amd64.exe`。
3. 在浏览器打开 `http://服务器IP:9527`；本机可使用 `http://127.0.0.1:9527`。
4. 使用初始密码 **`admin`** 登录，在“系统”中修改管理密码。

保持程序运行窗口开启。配置、证书、日志和历史默认保存在程序旁的 `data` 目录。

### Linux

解压软件包后，在程序所在目录执行：

```bash
chmod +x prl-relay-linux-amd64
./prl-relay-linux-amd64
```

随后访问 `http://服务器IP:9527`，使用 `admin` 登录并修改密码。

需要长期运行和开机启动时，可安装软件包附带的 systemd 服务：

```bash
sudo install -m 755 prl-relay-linux-amd64 /usr/local/bin/prl-relay
sudo install -m 644 prl-relay.service /etc/systemd/system/prl-relay.service
sudo systemctl daemon-reload
sudo systemctl enable --now prl-relay
sudo systemctl status prl-relay
```

安装服务前先停止前台运行的程序，避免端口冲突。服务的数据目录为 `/var/lib/prl-relay/`；若已有配置与历史，请在启动服务前迁移对应数据，并确保服务账户能够读写。

### 默认设置

| 项目 | 默认值 |
| --- | --- |
| 后台监听 | `0.0.0.0:9527`，普通 HTTP |
| 初始管理密码 | `admin`，登录后提示修改 |
| 初始矿机端口 | `3333`，SSL |
| 初始上游 | PRL Kryptex：`prl.kryptex.network:8048`，SSL |
| SSL 证书 | 首次启动自动生成自签证书 |
| 转发抽水 | 0%，按端口自行配置 |
| 日志保留 | 7 天，可调整 |
| 定时备份 | 每 24 小时，保留最近 7 份，可调整 |

在服务器防火墙和云平台安全组放行管理端口，以及实际使用的矿机接入端口。管理入口可在“系统”中修改监听范围、端口和 HTTPS 开关；矿机 SSL 与后台 HTTP 相互独立。

## 配置转发端口

1. 打开“矿池”，选择 PRL 或 QTC，展开目标矿池。
2. 使用“测速”比较地区节点，也可分别检测 TCP / SSL。结果是**转发服务器到矿池**的连接耗时。
3. 点击节点旁的“选用”，或到“端口”点击“添加端口”。
4. 设置监听端口、矿机接入是否使用 SSL、矿池节点及上游 SSL。
5. 根据需要填写转发抽水比例和收款钱包；不需要转发抽水时保持 0%。
6. 按需设置查询密码，保存后让矿机连接该转发端口。

例如 PRL 使用 `3333`，QTC 新建 `3334`。多个转发端口可以选择不同矿池、节点、连接方式和转发抽水比例。未收录的矿池可在“矿池”中自定义添加。

SSL 上游默认校验证书。自签上游可在端口高级设置中提供 CA；使用 IP 连接而证书签给域名时，可设置证书域名。

## SRBMiner 3.7.6 接入示例

将 `SERVER_IP` 替换为转发服务器地址，将钱包替换为矿工自己的对应币种钱包。以下示例要求对应转发端口已经开启 SSL。

PRL：

```bat
SRBMiner-MULTI.exe --algorithm-gpu pearlhash --pool SERVER_IP:3333 --wallet YOUR_PRL_WALLET --worker rig01 --tls true --disable-cpu
```

QTC：

```bat
SRBMiner-MULTI.exe --algorithm-gpu quantus --pool SERVER_IP:3334 --wallet YOUR_QTC_WALLET --worker rig01 --tls true --disable-cpu
```

如果端口配置为 TCP，将 `--tls true` 改为 `--tls false`。端口是否启用 SSL 必须与矿工参数一致。

## 查询与统计

在“端口”点击“查询”，即可打开或复制该端口的查询链接，格式为：

```text
http://服务器IP:9527/p/端口ID
```

设置了查询密码时，访问者需要先输入该端口的密码。查询密码留空表示公开查询；查询凭据不能进入管理后台。

“在线矿工”直接显示此端口全部在线连接，无需先输入钱包。每 5 秒更新，支持名称搜索和每页 50 / 100 / 200 条；同名连接分别显示，没有名称时标记为“未命名矿工”。矿工名称取自矿工软件的 worker / rigid 或账户后缀，钱包地址与矿工 IP 不在在线列表中公开。

输入完整钱包地址或矿池账户，可查看该端口下对应钱包的在线连接、矿机名称、最近活动时间、接受 / 拒绝 / 未知份额、上传 / 下载。请勿添加 `.worker` 或 `/worker` 后缀，查询区分大小写。

- 流量和份额统一展示**滚动最近 24 小时**；连接数是当前在线值。
- 流量按矿工上传 / 下载的应用数据计量，不包含 TCP/IP 和 TLS 封装。
- 钱包数据可在矿机离线或程序重启后继续查询；统计不是链上余额或矿池付款记录。
- 历史保存 30 天，页面展示最近 24 小时；正常退出保存尾段，突然断电可能丢失最近约一分钟尚未落盘的数据。

## 转发抽水与开发者费

转发抽水按端口独立设置，默认 0%。程序固定开发者费为 **0.2%（千分之二）**。两项均按总任务分配时间计算，矿工软件和矿池自身费用另计。

任务和计算结果绑定原矿池连接，切换通道后迟到的结果仍提交给原连接。短时间内的份额数量和收益比例会受任务难度、份额随机性与暂停影响，不应直接当作时间费率。

## 日志、导入导出与备份

- **日志**：按日期和级别筛选；在“系统”设置保留周期，支持 1–365 天，默认 7 天。
- **设置导出**：在“系统”下载配置 JSON。
- **设置导入**：选择配置 JSON，先预览再应用。导入保留当前管理密码；校验、端口绑定或保存失败时保留原服务。
- **自动备份**：支持每 1–168 小时备份一次，保留 1–90 份；默认每 24 小时备份、保留 7 份。
- **立即备份**：手动生成 ZIP，完成后可以下载。

备份包含设置、证书、日志和统计数据，存放在 `data/backups/`。恢复完整备份时先停止程序，再把 ZIP 解压到数据目录，使 `config.json`、`history/`、`wallets/`、`logs/` 位于同一级，随后启动。完整恢复会恢复备份中的管理密码。

设置导出和备份含认证信息与证书私钥，请妥善保存。默认 HTTP 不加密后台密码传输，可限制管理端口访问来源，或在“系统”启用 HTTPS。

## 重启软件

登录后台，在“系统”中点击“重启软件” → “确认重启”。请先保存正在编辑的设置。软件保存统计尾段并重新启动，网页在检测到服务恢复后自动返回登录页；配置、证书、密码和历史保留。

矿工会短暂断开，由矿工软件自动重连。断开前未收到回执的份额记为“未知”，不会自动重放。管理和查询会话需要重新登录。重启使用网页当前保存的配置，不重复执行启动时的临时密码或端口覆盖参数。

此按钮仅管理员可用。Linux 使用 exec 保留被服务管理器跟踪的 PID；Windows 启动新进程后退出旧进程。若 90 秒仍未恢复，页面会提示刷新或检查服务器日志。

## 升级

1. 正常停止旧程序。
2. 备份并保留完整 `data` 目录；使用自定义配置路径或 systemd 时，保留对应数据目录。
3. 替换为新版可执行文件，再启动。

配置会自动迁移，保留转发抽水、管理密码、证书和矿池设置；旧的开发者费设置会统一为本版固定值。升级前未记录的钱包明细无法补齐。旧配置中已移除的 Pearlhash 矿池端口会停用。

## 常见问题

**后台打不开**：检查程序是否运行、9527 是否被占用，以及防火墙 / 安全组是否放行。默认使用 `http://`，不是 `https://`。

**矿机连接不上**：检查监听端口、矿工 TCP / SSL 参数、矿池节点可用性，以及钱包或矿池账户格式。可先在后台测速，再查看日志。

**Pearlhash 是否支持**：PRL 的 `pearlhash` 算法支持；名为 Pearlhash 的矿池未收录。

**有算力但短时间没有份额**：份额产生具有随机性，也受矿池难度影响。结合矿工日志、任务接收和矿池回执判断，连通测速不代表钱包认证或有效份额已通过。
